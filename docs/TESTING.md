UI 测试使用 `-demoMode` 注入确定性音频和位姿，覆盖：

1. 首页从用户问题进入，不以仪器名称作为入口。
2. 权限解释、录制和持续低频检出。
3. 1 个起点、2 个候选实测点、每个候选后的起点复测和实测点建议。
4. 调整前、一次调整、调整后和变化判定。

真机专用 XCUI 用例再覆盖两条硬件边界：

1. `test-device-audio` 使用真实麦克风录制 20 秒，接受“检出”或“未检出”，但拒绝“测量无效”，并保存实际采样率、输入名称和通道证据。
2. `test-device-ar` 使用按真实 20 秒节奏生成的确定性声学输入，同时保留真实 ARKit、相机和位姿监控。`-realPoseTest` 只有与 `-uiTesting` 同时出现才生效，测试历史使用内存仓库。

## 自动化证据的边界

- 合成正弦和噪声可以验证数学标度、频率估计和失效门槛，不能代表 iPhone 麦克风频响。
- 模拟 AR 位姿可以验证 epoch、闭合和排名规则，不能代表真实房间中的跟踪漂移。
- 模拟器构建可以验证 iOS API 编译，不能代表音频路由、中断、数据源或实时回调性能。

## 2026-08-08 真机证据

设备：iPhone 13 Pro，iOS 26.5.2，有线连接，开发者模式开启。仓库不记录设备序列号、UDID、签名团队或原始录音。

| 验证 | 结果 | 证据范围 |
| --- | --- | --- |
| 签名、安装与启动 | 通过 | 自动签名构建安装并由 XCTest 启动 |
| 设备核心测试 | 61/61 通过 | 6 个测试组；源文件文案检查为主机专用 |
| 确定性 UI 流程 | 4/4 通过 | 首页、嗡声检查、逐候选 A-B-A 空间流程、前后比较 |
| 真实麦克风 | 通过 | 连续录制 20 秒；实际 48,000 次/秒；`iPhone麦克风 / 下`；1 个输入通道，分析第 1 个；本次环境正确返回“未检出” |
| 真实 ARKit 起点 | 通过 | 相机和 ARKit 来自真机；确定性声学输入按 20 秒节奏运行；位姿全程保持正常；起点成功加入实测位置 |
| 环境声与 AR 集成 | 安全拒绝/跳过 | 首次因目标频率未稳定复现而拒绝起点；第二次房间无持续音而跳过。未将环境变化误报为位置差异 |

真机测试发现并修正了两个模拟器未暴露的问题：

- 音频会话激活后延迟到达、但实际输入未改变的路由通知曾使测量误判无效；现在比较起始与当前路由 ID。
- Swift 6 在实时音频队列检查到主 actor 隔离闭包并触发崩溃；tap 现在使用显式 `@Sendable` 回调，把数据交给线程安全累加器。
