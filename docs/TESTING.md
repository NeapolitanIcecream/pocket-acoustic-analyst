UI 测试使用 `-demoMode` 注入确定性音频和位姿，覆盖：

1. 首页从用户问题进入，不以仪器名称作为入口。
2. 权限解释、录制和持续低频检出。
3. 间歇音调的出现比例、不能比较位置的原因、历史记录和详情页。
4. 1 个起点、2 个候选实测点、每个候选后的起点复测和实测点建议。
5. 调整前、一次调整、调整后和变化判定。
6. 多音调结果进入三轮状态调查，完成 7 次录音、保存并在历史中找到分组结果。

真机专用 XCUI 用例再覆盖两条硬件边界：

1. `test-device-audio` 使用真实麦克风录制 20 秒，接受六类有效声音描述，但拒绝“测量无效”，并保存实际采样率、输入名称、通道、候选频率、出现比例和变化证据。
2. `test-device-ar` 使用按真实 20 秒节奏生成的确定性声学输入，同时保留真实 ARKit、相机和位姿监控。`-realPoseTest` 只有与 `-uiTesting` 同时出现才生效，测试历史使用内存仓库。

## 自动化证据的边界

- 合成正弦和噪声可以验证数学标度、频率估计和失效门槛，不能代表 iPhone 麦克风频响。
- 模拟 AR 位姿可以验证 epoch、闭合和排名规则，不能代表真实房间中的跟踪漂移。
- 模拟器构建可以验证 iOS API 编译，不能代表音频路由、中断、数据源或实时回调性能。

真机测试发现并修正了两个模拟器未暴露的问题：

- 音频会话激活后延迟到达、但实际输入未改变的路由通知曾使测量误判无效；现在比较起始与当前路由 ID。
- Swift 6 在实时音频队列检查到主 actor 隔离闭包并触发崩溃；tap 现在使用显式 `@Sendable` 回调，把数据交给线程安全累加器。

本轮同一房间的三次真实麦克风复测提供了以下现场证据：

| 次数 | 声音描述 | 时间证据 | 可支持的判断 |
| --- | --- | --- | --- |
| 1 | 持续低频，主要约 54 Hz；另有约 433 Hz 倍数成分 | 出现时段 100%；频率离散 0.05 Hz；强弱离散 1.1 dB；中等可信度 | 当时存在稳定、可锁定的窄带低频，适合继续做位置复测 |
| 2 | 多个低频音调；主要候选约 216 Hz，界面同时列出约 107、431、167 Hz；另有约 433 Hz 倍数成分 | 主要候选出现时段 100%；频率离散 0.48 Hz；强弱离散 1.3 dB；中等可信度 | 相隔约两分钟后频谱主次关系改变，不应把单一频率当作唯一问题，也不应直接进入空间扫描 |
| 3 | 持续低频，主要约 54 Hz；另有约 216 Hz 倍数成分 | 出现时段 100%；频率离散 0.05 Hz；强弱离散 1.3 dB；中等可信度 | 54 Hz 在本轮三次测量中的两次重新成为稳定主成分，说明它具有短时可重复性 |

这三次结果与房间中空调、电脑和游戏同时运行的多源场景相容，但不能据此确定哪台设备产生了哪个频率。价值在于应用既找到了可重复的窄带结构，也在结构改变时停止空间归因并要求逐台改变设备状态后复测。因为现场没有受控参考信号，这组证据验证产品可用性和保守决策，不验证绝对频率准确度或声源识别准确度。
